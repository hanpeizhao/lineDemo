# 移动端响应式适配设计

## 目标

让 LINE API 测试台在手机窄屏上保持可读、可点击、无横向溢出，同时保留桌面端现有的双列卡片和信息密度。

## 范围

- 手机端页面内边距、横幅字号和状态标签适配窄屏。
- API Tab 在窄屏下允许横向滚动，按钮保持足够的触控高度。
- API 卡片在窄屏下改为单列，卡片头部上下排列，文档链接和运行按钮不再挤在同一行。
- JSON 输入框、结果区域和错误提示避免撑破页面。
- 桌面端保持当前双列 API 卡片布局。

## 不包含

- 不改变 API registry、运行逻辑和字段内容。
- 不隐藏关键 API 描述或测试结果。
- 不引入新的 UI 组件库或第三方响应式依赖。

## 方案

1. 仅补充少量 CSS：改动小，但无法充分解决卡片内部的窄屏排布。
2. 移动优先重排（采用）：以 767px 为边界，在窄屏重排卡片头部、Tab、按钮和状态区域；桌面端继续使用现有布局。
3. 手机专用紧凑模式：信息密度高，但会牺牲 API 描述和调试信息的可读性。

## 实现规则

- 页面在窄屏下使用 12px 左右边距，横幅和卡片内边距收缩到 16px。
- Tab 使用 `overflow-x: auto`，每个 Tab 不压缩文字，保证点击区域至少 44px 高。
- 卡片头部在窄屏下垂直排列，文档链接保持独立行。
- 主要操作按钮在窄屏下撑满卡片宽度。
- 输入框和结果 JSON 使用 `overflow-wrap: anywhere`，长文本可以在容器内换行。
- 通过现有 Vitest 测试验证响应式相关的 class 约定，并运行完整测试和生产构建。
